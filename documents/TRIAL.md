# 真实用户试用方案

> 目的：给比赛材料提供**可解释的**效果证据，而不是一句「大家觉得不错」。
> 截止时间：2027-01-15 前完成两轮；建议第 1 轮在 12 月上旬前启动。

## 一、要回答的问题

1. 用过的人，第二轮的答辩表现有没有变化？（总分、四维、陈述单元覆盖）
2. 变化是不是来自「报告指出了具体问题」？（看第二轮的检验点是否被问到、报告里的短板是否减少）
3. 体验上卡在哪里？（首轮加载、录音识别、报告等待、手机操作）

**不做**：对照实验、显著性检验、把变化归因给本工具。样本量小，材料里必须写清这一点。

## 二、招募

- 10–20 人，优先找**近期要答辩或做课程汇报**的同学（有真实讲稿可练）。
- 明确告诉他们：这是课程作业性质的试用，**讲稿内容只存在我自己的服务器上，可随时删除**。
- 用统一账号登录（如 `trial`），在「怎么称呼你」里填**代号**（P01、P02…），不要填真名。
  这样导出的数据天然匿名，也不用给每个人建账号。

## 三、两轮流程

**第 1 轮（约 20 分钟）**

1. 打开链接，登录，选「毕业答辩」。
2. 上传或粘贴自己的讲稿。
3. 确认摘要卡；如果 AI 理解错了，当场改一条再确认（记录是否发生改写）。
4. 至少答 3 轮（建议 10 轮），结束，看报告。
5. 按报告里的「下一步练习」改讲稿。
6. 填问卷 A。

**间隔 1–3 天**（让修改沉淀，不要当天连做两轮）。

**第 2 轮（约 20 分钟）**

1. 用修改后的讲稿再练一次，轮数相同。
2. 结束，看报告。
3. 填问卷 B。

## 四、自动导出的指标

试用结束后在项目根目录执行：

```bash
python tools/trial_export.py --out trials        # 匿名（默认）
python tools/trial_export.py --names --out trials-named   # 需要核对人名时
```

产出：

- `trials/sessions.csv`：每场的有效作答、计分题数、未计分轮次、陈述单元覆盖率、总分、四维得分。
- `trials/summary.md`：参与人数、场次数、**同人两轮前后对比**（总分、各维度、覆盖率）、每人明细。

材料里建议引用这四类数字：**平均总分变化、覆盖提升人数、第二轮重复短板数量、报告等待时间**。
全部可以从 CSV 算出来，不要手填。

## 五、问卷

用问卷星/腾讯问卷建两个一模一样的表单（A/B），每题 1–5 分（1 完全不同意，5 完全同意）。

**封闭题**

1. 这份报告指出的问题，和真实的答辩风险是一致的。
2. 报告里的证据（原话引用）能让我回忆起当时是怎么答的。
3. 「下一场要重点检验的点」让我知道下一次该准备什么。
4. 我按报告修改了讲稿或回答思路。
5. 手机上的操作（上传、录音、翻看报告）不费劲。
6. 等待报告的时间可以接受。
7. 我愿意在正式答辩前再用它练一次。
8. 我会推荐给同样要答辩的同学。

**开放题**

9. 报告里哪一条对你最有用？为什么？
10. 哪一处让你觉得「AI 没听懂我」或者「答非所问」？
11. 如果只能改一件事，你希望改什么？

## 六、数据与隐私

- 讲稿、问答、报告都存在运行服务的机器上（`.web-data/`），不进仓库。
- 参与者可以要求删除自己的场次（历史页 → 删除）；导出默认匿名。
- 比赛材料里只出现代号与聚合数字，不出现讲稿原文和真实姓名。
- 如果公网访问，务必启用登录账号；试用结束后可以改密码或停掉服务。
