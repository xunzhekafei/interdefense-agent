## 3 AI 交互记录

### 3.1 现状盘点与优先级

- **提示词（摘录）**：「这是我的软件创新大赛根目录，作品在 interdefense-agent 目录下，
  请看一下现在这个目录下的内容，决定我们下一步要做什么。文档里应该有初步的工作进度和计划。」
- **AI 回复要点**：读到改造已进行到前端三块界面但未提交；本机跑构建发现 `types.ts` 重复声明
  导致 `tsc` 失败（此前被误判为「沙箱卡顿」）；用真实模型跑通答辩闭环，指出最大缺口是
  评分仍是面试四维；建议先补评分口径，再移动端。
- **团队判断**：采纳「评分口径优先」，并确认「先在本机验收再提交」。

### 3.2 答辩四维评分与画像兼容

- **提示词（摘录）**：「下一步先做哪件？」→ 选择「答辩四维评分」。
- **AI 回复要点**：在单一来源模块中按场景定义维度与权重（方法与论证严谨性 35%、工作量与完整性
  25%、创新与个人贡献 25%、表达与应答 15%）；评分 schema、提示词、加权全部随场景走。
  AI 主动指出一个隐藏风险：画像聚合只认面试四维，直接上线会让答辩场次「静默消失」。
- **团队判断**：要求补「面试与答辩混在同一画像」的回归测试，确认不互相吞并后才上线。

### 3.3 报告过长（真实用户反馈）

- **提示词（摘录）**：「我只回答了一个问题，我感觉这个报告会不会太复杂了。」
- **AI 回复要点**：定位到三个原因——没有最小证据门槛、未覆盖单元逐条列编号、汇总提示词无长度约束；
  改为「有效回答少于 3 题不给分」，未覆盖只给一句话，优势/短板/建议各限 4 条，并禁止
  P0/P1/P2 这类工程编号。
- **团队判断**：接受 3 题门槛（「我觉得没啥问题」），并要求导出文件也能自证覆盖与锚定。

### 3.4 摘要卡 405（真实故障）

- **提示词（摘录）**：贴出服务端日志「`GET /api/sessions/<id>/summary-card 405 Method Not Allowed`」，
  并描述「前端一直显示在解析」。
- **AI 回复要点**：根因是前端调用 `api(path)` 未带请求体，而该封装在无 body 时发 GET；
  接口只接受 POST。更深一层：摘要卡组件在卡片为空时**无条件渲染加载动画**，失败没有出口。
  一并修复，并加「无 body=GET、有 body=POST」的回归测试。
- **团队判断**：要求任何 loading 状态必须有 error 状态与重试入口。

### 3.5 手机布局（真实用户反馈）

- **提示词（摘录）**：「手机端的体验不好，整个页面还是按照网页端的来做的，屏幕会乱晃，
  并且没有适应手机屏幕大小。」
- **AI 回复要点**：承认上一版把对话区高度改成 `auto`，消息不再内部滚动，输入框被内容顶着跑——
  这就是「乱晃」的直接原因；改为固定视口高度 + 内部滚动、顶栏吸附、隐藏开场大标语、
  安全区内边距、输入框 16px 防 iOS 缩放。
- **团队判断**：要求历史独立成页、顶部按钮重排，避免与删除按钮互相遮挡。

### 3.6 轮数不生效（真实用户反馈）

- **提示词（摘录）**：「面试轮数在答辩练习里没有生效，我选的 10 轮，但是到了这个数依然在问。」
- **AI 回复要点**：提示词只写了「按单元覆盖、每个单元至少问到一次」，轮数没有约束力；
  技能文件里也有同样矛盾的表述。改为题数硬上限 + 注入「目前已问 X 题」，到上限只做收尾。
- **团队判断**：要求技能与代码口径一致，并补两条回归测试。

### 3.7 语音功能缺失与版本兼容

- **提示词（摘录）**：「语音功能完全没有，目前好像没装这个功能。」
- **AI 回复要点**：确认 `/api/health` 的 `asr=false`；安装 CPU 版 faster-whisper，默认模型改为
  `small`（`large` 在 CPU 上太慢）；启动脚本补国内镜像。装完后实际转写报
  `TypeError: unexpected keyword argument 'metadata_errors'`——faster-whisper 1.2.1 与 PyAV 19
  不兼容。AI 没有锁版本（旧 wheel 下载失败），而是在代码里加兼容层丢弃该参数，并留回归测试。
- **团队判断**：要求用真实语音验证，而不是只看「模型加载成功」；最终用系统 TTS 合成 4 秒语音，
  转写 1.7 秒且逐字正确。

### 3.8 部署排错

- **提示词（摘录）**：贴出服务器输出：Node 18 与 Vite 7 不兼容、`EACCES`、
  `scp: stat remote: No such file or directory`。
- **AI 回复要点**：逐条给出根因——Node 版本不足；`sudo npm ci` 造成 root 属主；Windows scp 的
  SFTP 协商问题。改用「本机构建 + tar 管道上传」；发现自己给的 tar 命令保留了 `frontend/` 前缀，
  导致远端出现 `frontend/frontend/dist`，主动纠正并给出正确写法。
- **团队判断**：坚持旧服务不能停（评委演示账号在用），最终改为子域名 + 独立端口并存。

### 3.9 保留旧服务与双站点

- **提示词（摘录）**：「我之前的 myagent 服务还得开着，因为我有的比赛用的演示账号是那个，
  评委可能会用到。」
- **AI 回复要点**：改为「旧版 8010 + 答辩版 8011」双站点方案；确认 sslip.io 支持子域名解析；
  给出 nginx 配置（上传大小、WebSocket、长超时）与证书步骤；强调切换后要用旧账号「退出→重登」验证。
- **团队判断**：执行双站点并验证两套账号互不影响。

## 5 AI 生成内容核验

AI 的输出不是直接采信的，以下都是**被发现问题并修正**的例子：

| AI 输出 | 核验方式 | 结论与修正 |
| --- | --- | --- |
| 「前端构建卡在沙箱扫描 node_modules」 | 本机实际执行 `npm run build` | 实为 `tsc` 重复声明报错，修复后构建 1.1 秒完成 |
| 摘要卡接口「已可用」 | 真机操作 + 服务端日志 | 前端发成 GET 导致 405，修复并加测试 |
| 「答辩评分已切四维」 | 混场景画像测试 | 画像按面试四维取权重会让答辩场次消失，补兼容 |
| 报告「总分 2.0」 | 对比 summary 正文 | 正文由模型另算成 2.15，改为代码算分并写入提示词 |
| 「单元覆盖 3/5」 | 对照实际追问 | 模型漏标注导致漏算，加确定性回链（宁漏不错） |
| 语音「模型加载成功」 | 真实音频转写 | PyAV 19 兼容错误使转写直接失败，加兼容层 |
| tar 上传「已完成」 | 远端 `find` 校验 | 路径多套了一层 `frontend/`，纠正命令 |

## 6 过程总结

- **AI 帮助最大的地方**：把模糊需求变成可测的约束。例如「证据要有依据」落成「必须是逐字原文，
  否则重试」；「分数别乱跳」落成「均分与加权由代码计算」。
- **人工判断不可替代的地方**：给不给分、先做哪个平台、旧服务能不能停、样本量如何解读——
  这些没有标准答案，AI 容易给出「看起来合理」的方案，必须由人拍板。
- **最有效的工作方式**：先用测试或脚本复现问题，再让 AI 改；改完立刻跑回归；上线前用真实模型、
  真实手机、真实服务器各走一遍。AI 给出的结论要当成「待验证假设」，而不是结果。
- **不足**：接口文档与真实运行环境仍有差距（Node 版本、scp 协议、PyAV 兼容），这些只在部署时暴露；
  后续会把「环境自检脚本」纳入仓库，减少人工试错。
