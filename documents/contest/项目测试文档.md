## 1 测试计划

### 1.1 测试策略与目标

发布时的质量目标：**确定性逻辑可回归、模型行为可度量、关键流程在真机上走得通。**

分三层：

| 层级 | 做法 | 判定标准 |
| --- | --- | --- |
| 单元测试 | 纯函数与状态机，不调用模型；每个模块有独立测试文件 | 全部通过，且测试之间互不影响（`conftest` 把产物目录指向临时目录） |
| 功能测试 | FastAPI + WebSocket 的离线验收；上传、鉴权、PWA 资源单独覆盖 | 关键路径可用，失败时有明确错误而不是静默 |
| 系统测试 | 真实模型端到端；评测集 + LLM 裁判；性能计时 | 追问质量可对比、报告可复现、耗时在可接受范围 |

安全类问题单独立项：静默失败（禁止新增 `except Exception: pass`）、提示注入、上传文件防护。

### 1.2 测试范围

覆盖：陈述单元切分与回链、摘要卡与检验点、评分口径与证据校验、报告生成与导出、
讲稿导入、鉴权、场次存储与恢复、PWA 静态资源、语音识别链路。

不覆盖：模型厂商自身可用性、多租户隔离、大规模并发（当前是单机单工作线程 + 并行子任务）。

### 1.3 测试环境

| 项 | 配置 |
| --- | --- |
| 开发机 | Windows 11，Python 3.14，Node 22，Chrome / iPhone Safari |
| CI | Ubuntu + Windows，Python 3.14，按 `requirements-lock.txt` 安装 |
| 运行 | FastAPI + SQLite（WAL），前端 Vite 构建；DeepSeek flash 作为自动化模型 |
| 语音 | faster-whisper 1.2.1，CPU，`small` int8；PyAV 19 |
| 移动端 | iPhone（PWA 安装）、Android 模拟器（原生骨架） |

## 2 单元测试

自动化测试共 **392 个测试函数（收集 400 个用例）**，当前 **400 通过 / 2 跳过**；
前端另有 12 个 vitest 用例。按模块列出重点：

### 2.1 陈述单元与回链（`tests/test_units.py`，21 例）

| 用例 | 预期 |
| --- | --- |
| 标题映射段落类型 | 五个单元依次为背景/方法/结果/创新/局限 |
| 偏移逐字对应 | `原文[start:end] == unit.text` |
| 标题不进正文 | 单元文本不含 `## 研究背景` |
| 超长块切分 | 每段不超过上限，不丢弃内容 |
| 过短单元合并 | 「好的」不成为独立追问目标 |
| 模型漏标时回链 | 问题与单元共享 ≥6 字且领先次优 ≥4 字才补链；纯语义改写不猜 |

结果：21/21 通过。经验：**回链宁可漏、不可错**——报告说「这段没问到」是诚实缺省，
链错一段会让所有回链失去可信度。

### 2.2 摘要卡与检验点（`tests/test_summary_card.py`，16 例）

覆盖规则兜底、伪造单元编号丢弃、逐条改写/驳回、确认后生成下一场检验点、
**本场不继承自己的卡片**（真实缺陷回归）。结果 16/16。

### 2.3 评分口径（`tests/test_spec.py`，13 例）

场景维度互异、权重和为 1、跨场景权重算分、无效作答识别（复制题目/问候/跳过/反问）。
结果 13/13。

### 2.4 证据校验（`tests/test_evidence.py`，12 例）

证据必须是逐字原文；引号包裹、前缀词会被剥离；重试耗尽保留分数但标记未通过。
结果 12/12。

### 2.5 讲稿导入（`tests/test_script_import.py`，20 例）

UTF-8/GBK/UTF-16、Word 标题样式转 `##`、表格保留、PPT 每页成段、
旧格式 `.doc/.ppt` 拒绝并提示另存、PDF 拒绝、zip 炸弹与条目数上限、超长截断。
结果 20/20。

### 2.6 鉴权与画像

- `test_auth.py`：cookie 与 Bearer 双通道、登出即失效、WebSocket 带 token、
  登录限流。（8 例）
- `test_profile.py`：跨场次聚合、答辩与面试两套维度并存不吞并、旧口径兼容。（24 例）

**测试经验**：每一处真实缺陷都补了回归用例——摘要卡 405、检验点串场、报告两个总分、
单元标题污染、画像丢场次。测试不是「跑通」，而是「这次踩过的坑不会再踩」。

## 3 功能测试

### 3.1 答辩场次全流程

| 步骤 | 预期 | 结果 |
| --- | --- | --- |
| 上传 `.docx` 讲稿并创建答辩场次 | 返回场次与陈述单元 | 通过 |
| 生成摘要卡 | 每条主张绑定真实单元；模型不可用时规则兜底并标注 | 通过 |
| 确认摘要卡 | 进入对话，开场不要求自我介绍 | 通过 |
| 追问 3–6 轮 | 一次一题、锚定单元、达到题数上限收尾 | 通过 |
| 结束生成报告 | 四维答辩评分、逐题证据、单元覆盖、检验点 | 通过 |
| 导出 Markdown/PDF | 标题按场景、分数一致、含单元锚定 | 通过 |

真实模型端到端：3–6 题报告 **23–52 秒**，逐题流式返回；证据校验 4/4 通过。

### 3.2 移动端（PWA）

| 用例 | 预期 | 结果 |
| --- | --- | --- |
| 安装到桌面 | manifest + Service Worker 生效，独立窗口无地址栏 | 通过（iPhone） |
| 竖屏布局 | 顶栏固定、对话区内部滚动、输入框常驻底部 | 通过 |
| 弱网/后端未就绪 | `/api/health` 失败自动重试，按钮不会永久禁用 | 通过（缺陷回归） |
| 语音作答 | 录音 → 转写 → 填进输入框确认后提交 | 通过 |

### 3.3 安全与隐私

- 所有 API 与 WebSocket 受账号保护；健康检查与登录公开。
- 上传文件不可信：白名单、大小与解压体积上限、只读不落盘。
- 候选人资料按 JSON 数据处理，防提示注入。
- 场次可删除，删除后运行中的回合安全退出。

| --- | --- |

### 4.4 真实用户试用

用 `tools/trial_export.py` 导出总分、四维、陈述单元覆盖的前后变化，并配问卷。

状态：【待补】——样本量、前后对比数字、问卷结果。

### 4.5 测试缺口与风险

1. 模型评测基线停留在旧评分口径，v5 需重跑并建立新基线。
2. 答辩场景只有小样本真机验证，缺少 10 人以上的试用数据。
3. Android 原生客户端尚未编译验证（当前移动端以 PWA 为准）。
4. 单机部署，未做并发压力测试；2G 内存下语音模型与报告并行可能触发 OOM。
